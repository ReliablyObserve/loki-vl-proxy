This release enforces conservative request limits by default:
  - max-concurrent          = {{ index .Values.extraArgs "max-concurrent" | default "64" }}  (per-replica in-flight ceiling)
  - rate-limit-per-second   = {{ index .Values.extraArgs "rate-limit-per-second" | default "50" }}  (per-client token bucket refill, req/s)
  - rate-limit-burst        = {{ index .Values.extraArgs "rate-limit-burst" | default "100" }}  (per-client burst size)

These map to the proxy binary's --max-concurrent, --rate-limit-per-second,
and --rate-limit-burst flags.

To restore the previous unlimited behavior (NOT recommended — a single noisy
client can drive expensive fanout into VictoriaLogs), set all three back to
"0":

  helm upgrade {{ .Release.Name }} . \
    --set extraArgs.max-concurrent=0 \
    --set extraArgs.rate-limit-per-second=0 \
    --set extraArgs.rate-limit-burst=0

See docs/tuning.md for guidance on appropriate values for your workload
(Grafana replica count, p99 backend latency, backend headroom).

----

Admin / debug endpoints moved to loopback:
  /admin/*, /debug/pprof/*, /debug/queries now bind to 127.0.0.1:3101 inside
  the pod and are NOT exposed via the Service. Reach them with
  `kubectl exec` or `kubectl port-forward` rather than the cluster Service.

----

Metrics moved to a dedicated port:
  /metrics is now served on Service port `metrics` (:9091), not on the main
  Loki port (:3100). The chart's ServiceMonitor already targets the new
  port. If you scrape via your own Prometheus or a separately-managed
  ServiceMonitor, update its `port` from `http` to `metrics`.

----

The ServiceMonitor now sets `honorLabels: true`:
  the proxy's `endpoint` label (query_range, labels, ...) arrives as
  `endpoint` instead of `exported_endpoint`, and the scrape target's port name
  no longer overwrites it. Change `exported_endpoint` to `endpoint` in your own
  queries, or set serviceMonitor.honorLabels=false to keep the old labels.
  A scrape config you manage yourself needs `honor_labels: true` (Prometheus),
  or `honorLabels: true` (VMServiceScrape).

----

Peer cache shared token is required by default:
  The chart auto-generated Secret `{{ .Release.Name }}-peer-auth` holding a
  random token used for peer-to-peer cache auth. To rotate, replace, or
  externally manage this Secret, see
  docs/configuration.md#peer-cache-token-management.

----

Secrets are mounted as files:
  the peer, admin, delete and basic-auth Secrets reach the proxy through
  -...-file flags, not through process arguments or environment variables.
  The image must be of this chart's release or newer; an older proxy exits on
  the unknown flag. The proxy reads the files at startup, so restart the pods
  after rotating a Secret.
