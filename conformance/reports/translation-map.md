## drilldown-service-landing

**Logs Drilldown ranks services on the landing page**

### Loki layer

Drilldown calls `/index/volume` with `{service_name=~".+"}`,
`targetLabels=service_name`, `limit=5000`, `aggregateBy=series`. Loki answers
with ingested bytes per service, as a vector when every series has one sample,
with only the target labels in the metric map.

### VictoriaLogs layer

VictoriaLogs has no volume endpoint and no ingested-byte accounting; it can sum
the stored `_msg` length per group, and it stores service_name only when the
producer sent it.

### Proxy layer — proxy_side

`stats_query` with `sum_len(_msg)` grouped by the target labels.

## explore-logs-volume-json

**Grafana Explore renders the logs volume for a `| json` query**

### Loki layer

Explore sends `sum by (level, detected_level) (count_over_time({...} | json |
drop __error__ [$__auto]))`. Loki parses each line, excludes lines whose parser
failed unless the pipeline drops the error, groups by the level stream label and
by the detected_level it assigned at ingest, and returns a sparse matrix with
second timestamps and Loki-formatted values.

### VictoriaLogs layer

VictoriaLogs can count rows per bucket grouped by stored or unpacked fields
(`stats_query_range` with `unpack_json ... keep_original_fields`), but it has no
detected_level, no parser-error marker, no `_extracted` renaming, and its buckets
are `[T, T+step)` rather than Loki's `(T-range, T]`.

### Proxy layer — hybrid

`stats_query_range` + `unpack_json fields (...) keep_original_fields` +
`filter` for label filters, on an anchored sliding-bucket grid; the level
grouping is merged in Go over the aggregated series, never over raw rows.
