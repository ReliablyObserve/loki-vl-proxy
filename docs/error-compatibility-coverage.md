# Error Compatibility Coverage

Generated by `conformance/scripts/error_registry.py` from the recorded answers of a real Loki, the error-layer gates and the registry. Do not edit by hand.

The answers are those of Grafana Loki 3.7.9, recorded over HTTP on 2026-11-13. Every comparable row is replayed against the proxy by `TestLokiErrorAnswersReplay` (status, Content-Type, X-Content-Type-Options and body, byte for byte), and a live Loki is asked one representative row of every route, error kind and message by `TestCompat_ErrorAnswersLikeLoki` on the end-to-end stack. Rows the proxy still answers differently are listed in `conformance/registry/error-layer-known-differences.json`; that list may only shrink, and the replay test holds it equal to what the proxy really answers, which is what makes the percentages below measured and not declared.

Error kinds:

- **Parameters**: A request parameter, URL or form body Loki cannot read or does not accept (start, end, since, step, limit, direction, interval, delay_for, aggregateBy, URL escapes, oversize bodies).
- **LogQL syntax**: A query Loki cannot parse: empty, unterminated, bad tokens.
- **LogQL validation**: A query that parses but Loki rejects while checking it: matcher rules, stage compile errors, wrong query type for the route, aggregation and function rules.
- **Limits**: A request over a limit Loki enforces: query length, lookback, series, resolution.
- **Backend failure**: The storage behind the proxy fails or answers something the proxy cannot use: Loki answers 500, or its queue-full 429, in its own words.
- **Methods and routing**: A path Loki's router does not know, a method a route does not serve, a tail request that is no websocket upgrade.
- **Tenant**: A tenant header Loki or the proxy rejects.
- **Cancel and deadline**: The client goes away (499) or the request runs out of time (504).

## Order of Loki's checks

1. **request decoding**: The URL and form body are decoded first. Messages: `post-too-large`, `url-escape`, `url-semicolon`.
2. **parameters**: Parameters are read next, in the order end, start, limit, step and direction; an end not after the start and the 11,000-point resolution check come before the query is parsed. Messages: `aggregate-by`, `delay-for`, `direction`, `end-before-start`, `interval-negative`, `limit-not-positive`, `number`, `param-duration`, `param-number`, `step-duration`, `step-not-positive`, `step-overflow`, `step-too-many-points`.
3. **logql syntax**: The query text is parsed; a syntax error is answered before the query-length limit on query_range, and on tail before the parameters. Messages: `parse`, `parse-input-size`.
4. **limits**: The query-length limit follows the syntax check on query_range and comes before it on the metadata routes. Messages: `limit-lookback`, `limit-query-length`.
5. **logql validation**: Checks of a query that parsed (stage compilation, matcher rules, query type) come last. Messages: `instant-log-query`, `only-label-matchers`, `only-log-selector`.

The order was observed by sending 33 requests that carry two errors each to a real Loki (`internal/lokierr/testdata/loki_check_order.jsonl`) and is held in each message item.

## Ratchets

- `error-layer-known-differences.json`: the rows that still differ; its ceiling may only fall.
- `error-layer-known-leaks.json`: the backend-failure cells that still leak; its ceiling may only fall.
- `conformance/registry/baseline.json`: the two scores above may not drop, and `scripts/ci/check_conformance.py` fails when a message has no item, an item has neither a recorded answer nor a documented reason, or a matrix cell loses a check it had on the base branch. A re-recording that adds rows can lower a percentage without any regression: the recorder (`test/errorrecord`) only rewrites answers of existing rows.
- The pull request quality report shows both scores for the base and the pull request and fails on a drop.

## Regenerating

```bash
python3 conformance/scripts/error_registry.py        # items, matrix, scores and this page
LVP_LOKI_ERROR_ANSWERS_UPDATE=1 go test ./internal/proxy -run TestLokiErrorAnswersReplay   # after a proxy change, the known differences
go run ./test/errorrecord -loki http://localhost:13101   # re-record Loki's answers from a running stack
```
